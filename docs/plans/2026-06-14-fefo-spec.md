## 1. MỤC ĐÍCH & PHẠM VI

### 1.1. Mục đích
Đảm bảo mọi lô sản phẩm được **sử dụng theo đúng thứ tự ưu tiên hạn dùng**:
- **Lô đã mở nắp** (open-vial) → ưu tiên trước
- **Lô chưa mở** → theo hạn gốc (FEFO cổ điển)
- Áp dụng cho **cả 4 kho** (BULK + DAILY × HC-SP + VTYT)
- **Auto-pick lô** khi xuất, có cảnh báo nếu thủ kho chọn khác
- **Cảnh báo + cho phép dùng lô hết hạn** có lý do (vd: cấp cứu)

### 1.2. Phạm vi
- **Trong scope**:
  - Auto-pick lô theo FEFO khi xuất (xuất tuần, xuất lẻ, xuất hủy)
  - Hiển thị gợi ý FEFO khi thủ kho chọn lô thủ công
  - Override có lý do + audit log
  - Cảnh báo lô hết hạn (đã có ở SPEC #3, tích hợp tại đây)
  - Báo cáo FEFO compliance (tỷ lệ tuân thủ)
- **Ngoài scope**:
  - Lot-to-Lot Validation (SPEC riêng P1)
  - Open-vial tracking chi tiết (đã có ở SPEC #3)

### 1.3. Tuân thủ
- **QĐ 2429/BYT** Tiêu chí 7.2: Sử dụng vật tư theo hạn dùng
- **ISO 15189:2022** Điều 6.5.3: Kiểm soát hạn dùng

## 3. WORKFLOW

### 3.1. Workflow Auto-Pick FEFO

```
[Thủ kho] Mở phiếu xuất (xuất tuần / xuất lẻ)
        ↓
Chọn sản phẩm + nhập số lượng cần xuất
        ↓
[Hệ thống] Auto-pick lô theo thuật toán FEFO:
  1. Lọc lô có status = APPROVED, quantity > 0
  2. Nếu có lô đã mở nắp (open_vial_opened_at IS NOT NULL)
     → Ưu tiên lô có open_vial_expiration_date sớm nhất
  3. Nếu không có lô mở nắp
     → Lấy lô có expiration_date (hạn gốc) sớm nhất
  4. Nếu lô đầu tiên không đủ số lượng → pick tiếp các lô sau
        ↓
[UI] Hiển thị:
  - Lô được chọn (highlight)
  - Tổng số lô cần lấy (có thể > 1 nếu lô đầu không đủ)
  - Cảnh báo nếu lô FEFO sắp hết hạn (< 7 ngày)
        ↓
[Thủ kho] Xác nhận hoặc chọn lô khác (phải có lý do)
```

### 3.2. Workflow Override FEFO

```
[Thủ kho] Nhấn "Chọn lô khác"
        ↓
Hệ thống hiển thị danh sách tất cả lô + lý do nên dùng FEFO
        ↓
[Thủ kho] Chọn lô khác + bắt buộc nhập lý do:
  - "Lô FEFO bị recall, không dùng được"
  - "Lô FEFO hết hàng giữa chừng"
  - "Cấp cứu cần lô cụ thể"
  - "Khác" (mô tả chi tiết)
        ↓
Hệ thống cảnh báo (level WARNING):
  "Bạn đang chọn lô không theo FEFO. Điều này sẽ được ghi audit log."
        ↓
Nếu xác nhận → ghi audit, tiếp tục
Nếu hủy → quay lại auto-pick
```

### 3.3. Workflow dùng lô hết hạn (đã chốt: cảnh báo + cho phép có lý do)

```
[Thủ kho] Chọn lô đã EXPIRED (status = EXPIRED)
        ↓
Hệ thống CẢNH BÁO ĐỎ + yêu cầu:
  - Chọn lý do: "Cấp cứu", "XN không có lô khác", "Khác"
  - Mô tả chi tiết (bắt buộc, > 50 ký tự)
  - Xác nhận chịu trách nhiệm
        ↓
[DEPT_HEAD] Nhận notification NGAY LẬP TỨC
        ↓
[Thủ kho] Nhấn "Dù dù lô hết hạn" → tiếp tục
        ↓
Hệ thống:
  - Ghi audit CRITICAL
  - Tạo investigation task
  - Đánh dấu lô cần kiểm tra chất lượng kết quả XN
```

### 3.4. Workflow FEFO Compliance Report

```
[DEPT_HEAD] Mở app → /reports/fefo-compliance
        ↓
Chọn tháng/năm + mảng
        ↓
Báo cáo:
  - Tổng số lần xuất
  - Số lần tuân thủ FEFO
  - Số lần override (kèm lý do)
  - Số lần dùng lô hết hạn
  - Tỷ lệ compliance (%)
  - Top 5 sản phẩm hay bị override
  - Top 5 thủ kho override nhiều nhất (cảnh báo)
```

## 4. LOGIC FEFO

### 4.1. Thuật toán Auto-Pick (đã chốt: open-vial trước, FEFO cho lô chưa mở)

```sql
-- Function: pick lots theo FEFO
CREATE OR REPLACE FUNCTION fn_pick_lots_fefo(
  p_product_id UUID,
  p_warehouse_id UUID,
  p_quantity_needed DECIMAL
)
RETURNS TABLE(
  lot_id UUID,
  lot_number TEXT,
  quantity_available DECIMAL,
  expiration_date DATE,
  open_vial_expiration_date DATE,
  pick_priority INT
) AS $$
BEGIN
  RETURN QUERY
  WITH eligible_lots AS (
    SELECT
      l.id,
      l.lot_number,
      l.quantity,
      l.expiration_date,
      l.open_vial_expiration_date,
      l.open_vial_opened_at,
      -- Tính "effective expiration" cho sort:
      -- Nếu đã mở nắp → dùng open_vial_expiration_date
      -- Nếu chưa mở → dùng expiration_date (gốc)
      COALESCE(l.open_vial_expiration_date, l.expiration_date) AS effective_expiration,
      -- Priority: lô mở nắp = 0 (cao nhất), lô chưa mở = 1
      CASE
        WHEN l.open_vial_opened_at IS NOT NULL THEN 0
        ELSE 1
      END AS priority_group
    FROM lots l
    WHERE l.product_id = p_product_id
      AND l.warehouse_id = p_warehouse_id
      AND l.status = 'APPROVED'
      AND l.quantity > 0
      AND l.expiration_date >= CURRENT_DATE  -- Loại lô hết hạn (trừ khi user chọn override)
      AND l.recall_notice_id IS NULL  -- Loại lô bị recall
  )
  SELECT
    el.id,
    el.lot_number,
    el.quantity,
    el.expiration_date,
    el.open_vial_expiration_date,
    ROW_NUMBER() OVER (
      ORDER BY el.priority_group ASC, el.effective_expiration ASC
    )::INT
  FROM eligible_lots el
  ORDER BY el.priority_group ASC, el.effective_expiration ASC;
END;
$$ LANGUAGE plpgsql;
```

### 4.2. Ví dụ minh họa

**Sản phẩm**: Glucose, cần xuất 10 chai từ BULK_HC_SP

| Lô | Status | HSD gốc | Open-vial exp | Opened? | Priority |
|---|---|---|---|---|---|
| L001 | APPROVED | 12/06/2026 | 16/06/2026 | Có (10/05) | **1** (cao nhất) |
| L002 | APPROVED | 17/06/2026 | - | Chưa | 2 |
| L003 | APPROVED | 20/06/2026 | - | Chưa | 3 |

**Kết quả FEFO**:
1. L001 (5 chai, đang mở, sắp hết open-vial exp)
2. L002 (5 chai, lô tiếp theo theo hạn gốc)
→ Tổng đủ 10 chai.

### 4.3. Logic khi lô FEFO không đủ

```
# Nếu lô FEFO đầu tiên < số lượng cần:
1. Lấy hết lô đầu
2. Pick tiếp lô ưu tiên tiếp theo
3. Lặp đến khi đủ số lượng
4. Nếu vẫn không đủ → báo "Không đủ tồn kho"
```

### 4.4. Edge cases

| Tình huống | Xử lý |
|---|---|
| Tất cả lô đều đã mở nắp → cùng priority_group = 0 | Sort theo open_vial_expiration_date |
| 2 lô cùng hạn + cùng open-vial status | Lấy lô có quantity lớn hơn trước (giảm số lô) |
| Lô FEFO đã bị thủ kho khác "đặt trước" | Vẫn pick (chưa có optimistic lock) |
| Lô sắp hết hạn (< 7 ngày) | Cảnh báo vàng + gợi ý dùng trước |
| Lô có `open_vial_expiration_date` < hôm nay | Vẫn pick nếu user chọn + lý do (cấp cứu) |
| Lô BLOCKED (recall) | Loại khỏi FEFO, không pick |
| Lô QC_FAILED / DESTROYED | Loại khỏi FEFO |
| Tất cả lô đều hết hạn | FEFO trả về rỗng, báo "Cần nhập hàng mới" |
| Lô có `quantity` thực tế < sổ (sai lệch chưa kiểm kê) | Vẫn pick theo quantity trong DB (giả định đúng) |
| Lô `open_vial_quantity_remaining` rất nhỏ (vd: 0.5ml) | Vẫn pick, thủ kho sẽ thấy cảnh báo "Lô gần hết" |

```sql
-- ============================================================
-- MODULE #3: FEFO ENFORCEMENT

-- ============================================================

-- 5.1. Bảng fefo_override_log (audit trail cho mọi lần override FEFO)
CREATE TABLE fefo_override_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,

  -- Context
  reference_type TEXT NOT NULL,             -- 'WEEKLY_REPLENISHMENT' | 'STOCKTAKE' | 'MANUAL_ISSUE' | 'TRANSFER'
  reference_id UUID NOT NULL,               -- ID của document
  product_id UUID NOT NULL REFERENCES products(id),

  -- Lô được chọn
  selected_lot_id UUID NOT NULL REFERENCES lots(id),
  recommended_lot_id UUID REFERENCES lots(id),  -- Lô FEFO recommend (có thể NULL nếu không có)
  selected_expiration DATE NOT NULL,
  recommended_expiration DATE,
  expiration_diff_days INT,                 -- = selected - recommended (dương = chọn lô muộn hơn)

  -- Lý do
  override_reason_category TEXT NOT NULL,   -- 'RECALL' | 'OUT_OF_STOCK' | 'EMERGENCY' | 'QUALITY' | 'OTHER'
  override_reason TEXT NOT NULL,            -- Mô tả chi tiết

  -- Lô hết hạn?
  used_expired_lot BOOLEAN DEFAULT FALSE,   -- TRUE nếu chọn lô đã EXPIRED
  expired_lot_acknowledgment TEXT,          -- Cam kết chịu trách nhiệm

  -- Người thực hiện
  performed_by UUID NOT NULL REFERENCES auth.users(id),
  performed_at TIMESTAMPTZ DEFAULT now(),

  -- Notification cho DEPT_HEAD
  dept_head_notified BOOLEAN DEFAULT FALSE,
  dept_head_notified_at TIMESTAMPTZ,

  -- Investigation task (nếu dùng lô hết hạn)
  investigation_task_id UUID,

  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_fefo_log_tenant ON fefo_override_log(tenant_id, performed_at DESC);
CREATE INDEX idx_fefo_log_product ON fefo_override_log(product_id);
CREATE INDEX idx_fefo_log_user ON fefo_override_log(performed_by);

-- 5.2. Bảng fefo_compliance_monthly (cached report - update hàng tháng)
CREATE TABLE fefo_compliance_monthly (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,

  period_year INT NOT NULL,
  period_month INT NOT NULL,
  product_group TEXT,                       -- HC-SP / VTYT / NULL = tất cả
  warehouse_role warehouse_role,            -- NULL = tất cả

  total_issues INT DEFAULT 0,               -- Tổng số lần xuất
  fefo_compliant INT DEFAULT 0,             -- Số lần tuân thủ FEFO
  fefo_overrides INT DEFAULT 0,             -- Số lần override
  expired_lot_usage INT DEFAULT 0,          -- Số lần dùng lô hết hạn
  compliance_rate DECIMAL(5, 2),           -- % tuân thủ

  -- Top override reasons
  top_override_reasons JSONB,              -- [{reason, count}]
  top_overridden_products JSONB,            -- [{product_id, product_name, count}]
  top_override_users JSONB,                 -- [{user_id, email, count}]

  generated_at TIMESTAMPTZ DEFAULT now(),

  UNIQUE (tenant_id, period_year, period_month, product_group, warehouse_role)
);

-- 5.3. Function: pick lots theo FEFO (đã ở mục 4.1)
-- fn_pick_lots_fefo(p_product_id, p_warehouse_id, p_quantity_needed)

-- 5.4. Function: ghi log override
CREATE OR REPLACE FUNCTION fn_log_fefo_override(
  p_reference_type TEXT,
  p_reference_id UUID,
  p_product_id UUID,
  p_selected_lot_id UUID,
  p_recommended_lot_id UUID,
  p_override_reason_category TEXT,
  p_override_reason TEXT,
  p_used_expired_lot BOOLEAN,
  p_expired_lot_acknowledgment TEXT
)
RETURNS UUID
LANGUAGE plpgsql
AS $$
DECLARE
  v_log_id UUID;
  v_selected_exp DATE;
  v_recommended_exp DATE;
  v_user_id UUID;
BEGIN
  v_user_id := auth.uid();

  SELECT expiration_date INTO v_selected_exp FROM lots WHERE id = p_selected_lot_id;
  IF p_recommended_lot_id IS NOT NULL THEN
    SELECT expiration_date INTO v_recommended_exp FROM lots WHERE id = p_recommended_lot_id;
  END IF;

  INSERT INTO fefo_override_log (
    tenant_id, reference_type, reference_id, product_id,
    selected_lot_id, recommended_lot_id,
    selected_expiration, recommended_expiration, expiration_diff_days,
    override_reason_category, override_reason,
    used_expired_lot, expired_lot_acknowledgment,
    performed_by
  ) VALUES (
    (SELECT tenant_id FROM auth.users WHERE id = v_user_id),  -- Lấy tenant từ user
    p_reference_type, p_reference_id, p_product_id,
    p_selected_lot_id, p_recommended_lot_id,
    v_selected_exp, v_recommended_exp,
    CASE WHEN v_recommended_exp IS NOT NULL THEN v_selected_exp - v_recommended_exp ELSE NULL END,
    p_override_reason_category, p_override_reason,
    p_used_expired_lot, p_expired_lot_acknowledgment,
    v_user_id
  )
  RETURNING id INTO v_log_id;

  -- Nếu dùng lô hết hạn → notify DEPT_HEAD
  IF p_used_expired_lot THEN
    PERFORM fn_notify_dept_head_critical(
      'FEFO_EXPIRED_LOT',
      format('Thủ kho %s vừa dùng lô hết hạn: %s. Lý do: %s',
        (SELECT email FROM auth.users WHERE id = v_user_id),
        (SELECT lot_number FROM lots WHERE id = p_selected_lot_id),
        p_override_reason
      )
    );
  END IF;

  RETURN v_log_id;
END;
$$;

-- 5.5. Cron: update compliance report hàng tháng

-- 5.6. RLS
ALTER TABLE fefo_override_log ENABLE ROW LEVEL SECURITY;
ALTER TABLE fefo_compliance_monthly ENABLE ROW LEVEL SECURITY;

CREATE POLICY "rls_fefo_log" ON fefo_override_log

      SELECT id FROM products WHERE product_group = ANY(fn_user_product_groups())

  );

CREATE POLICY "rls_fefo_compliance" ON fefo_compliance_monthly
  FOR SELECT USING (true);  -- Tất cả thấy được

COMMENT ON TABLE fefo_compliance_monthly IS 'Cache báo cáo FEFO compliance theo tháng';
```

## 8. EDGE CASES

| Tình huống | Xử lý |
|---|---|
| 2 thủ kho cùng pick lô → quantity âm | Optimistic lock + check trước khi confirm |
| Lô FEFO bị recall giữa chừng | Re-pick lô khác, cảnh báo |

| User chọn lô + lý do "Khác" nhưng mô tả < 20 ký tự | Validation fail |
| DEPT_HEAD xem báo cáo compliance | Thấy tất cả thủ kho trong khoa |
| Thủ kho thường xuyên override (≥ 5 lần/tháng) | Cảnh báo cho DEPT_HEAD, có thể training lại |
